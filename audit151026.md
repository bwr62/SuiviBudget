```
     types/       # Types partages client
```

**Verdict** : Architecture propre et coherente. La separation des responsabilites est bien respectee : routeur -> service -> base de donnees.

### 4.2 Points d'Analyse Backend

**[OK] Routes api.ts bien structurees**
- 7 sections logiques clairement separees par des commentaires
- Validation Zod systematique sur tous les payloads entrants
- Transactions SQLite ACID sur les operations multi-tables

**[ATTENTION] Taille de api.ts (731 lignes)**
Le fichier api.ts gere 7 domaines fonctionnels distincts en 731 lignes. Il devient difficile a maintenir.
Recommandation : decouper en routeurs thematiques (monthsRouter, transactionsRouter, categoriesRouter, statsRouter, backupRouter, onboardingRouter).

**[ATTENTION] Pas de couche de service dediee aux routes**
La logique metier est melangee aux controleurs dans api.ts. La creation d'un recurring_template lors du POST /transactions est codee directement dans le handler HTTP.
Recommandation : extraire les operations SQL des routes dans des services dedies.

**[RISQUE] Absence de gestion d'erreur globale**
Les routes ne disposent pas d'un middleware errorHandler centralise.

**[RISQUE] 'any' omnipresent dans les handlers**
Dans api.ts, les resultats de db.prepare().get() sont castes en 'any' pour contourner le typage strict.
Exemple : const tx = db.prepare(...).get(id) as any;
Recommandation : utiliser les interfaces definies dans schema.ts.

| auth_challenges avec TTL applicatif | OK | Challenges WebAuthn persistes en base, immunise aux redemarrages |

### 5.2 Schema - Risques & Manques

**[ATTENTION] Absence d'index sur transactions.template_id**
La requete UPDATE transactions WHERE template_id = ? AND month_year >= ? scanne toute la table si template_id n'est pas indexe.
```sql
-- Index manquant recommande :
CREATE INDEX IF NOT EXISTS idx_transactions_template_id ON transactions(template_id);
```

**[ATTENTION] Pas de migration versionnee**
Le schema est cree avec CREATE TABLE IF NOT EXISTS. Si une colonne est ajoutee, les bases existantes ne sont pas mises a jour automatiquement.
Recommandation : implémenter un systeme de migration simple (table schema_versions + scripts SQL numerotes).

**[ATTENTION] Colonne is_closed sur monthly_balances non exploitee**
La colonne is_closed INTEGER DEFAULT 0 est definie mais aucune route API ne permet de cloture un mois.

**[INFO] Type amount REAL - Precision flottante**
Les montants sont stockes en REAL (double flottante). Pour des raisons de precision comptable, il est recommande de stocker les montants en centimes entiers (INTEGER) et de diviser par 100 a l'affichage.

### 5.3 Coherence Donnees

- [OK] La derivation month_year = date.substring(0, 7) est coherente backend ET frontend
- [OK] La cascade ON DELETE CASCADE sur subcategories -> categories est correcte
- [OK] ON DELETE SET NULL sur transactions -> recurring_templates protege l'historique
- [ATTENTION] La suppression d'une subcategory ne reassigne pas les transactions orphelines

## 6. ANALYSE SECURITE

### Note Globale Securite : 9/10

| Vecteur | Statut | Commentaire |
| :--- | :---: | :--- |
| Injection SQL | ELIMINE | 100% Prepared Statements verifies |
| XSS | Mitige | Cookie HttpOnly + CSP via Helmet |
| CSRF | Mitige | SameSite=Strict + Origin CORS verrouillee |
| Brute Force Auth | Protege | express-rate-limit sur routes /api/auth/* |
| Clonage Passkey | Protege | Compteur de signatures (counter) stocke en DB |
| Challenge WebAuthn volatile | CORRIGE | Table auth_challenges SQLite avec TTL 5 min |
| Entropie JWT insuffisante | PROTEGE | Crash preventif si JWT_SECRET.length < 32 |
| Tokens de secours faibles | PROTEGE | Argon2id (resistant aux attaques GPU/ASIC) |
| Exposition des donnees utilisateur | Partiel | Export JSON inclut les hash de recovery - a filtrer |
| Absence de Refresh Token | Manquant | CDC preconise Access Token 15 min + Refresh Token 7 jours |

### Detai : Export JSON & Confidentialite
La route GET /api/backup/export/json exclut correctement le recovery_hash.
Cependant, les cles publiques des passkeys ne sont pas exportees, rendant l'export JSON non-restoreable complet.

### Detail : Absence de Refresh Token
Le CDC specifie : "Access Token (15 min) + Refresh Token (7 jours, stocke et revocable en base)".
Seul un JWT longue duree est implemente. Pour un usage local c'est acceptable, mais non conforme au CDC.

## 9. POINTS FORTS (ATOUTS MAJEURS)

### EXCELLENCE 1 - Moteur de Report Mensuel (10/10)

La RolloverEngine est le composant le plus sophistique du projet. Elle resout elegamment des problemes complexes :
- Idempotence garantie par un index UNIQUE SQL (pas par du code applicatif fragile)
- ACID grace aux transactions better-sqlite3 synchrones
- Exclusion PENDING en une seule passe SQL avec CASE WHEN
- Propagation temporelle avec portee (scope) et loi d'integrite historique inviolable
- Extinction automatique des credits a date via end_month_year

### EXCELLENCE 2 - Securite WebAuthn (9/10)

L'authentification sans mot de passe est rarement implementee correctement dans les projets personnels. Ici :
- Challenge SQLite avec TTL (resistant aux redemarrages)
- Compteur de signatures anti-clonage
- Code de secours Argon2id (le meilleur algorithme actuel)
- Entropie JWT verifiee au demarrage avec crash preventif

### EXCELLENCE 3 - Documentation Vivante knowledge.md (10/10)

Le fichier knowledge.md est une source de verite maintenue a jour a chaque version avec :
- Changelog detaille (v0.01 -> v0.05)
- Registre exhaustif des fichiers (35 entrees)
- Schema DB documente
- Contrats d'API complets
- Logique metier expliquee

C'est une pratique professionnelle rare et precieuse.

### EXCELLENCE 4 - Onboarding Wizard (UX Soignee)

L'assistant de premiere connexion en 6 etapes avec :
- Personnalisation multi-forfaits mobiles avec libelles nominatifs
- Calcul en temps reel du reste a vivre dans l'etape de synthese
- Validation atomique en une transaction SQLite
- Decoupage modulaire en sous-composants dedies

### EXCELLENCE 5 - Derivation de Date (Correction Metier Critique)

La correction month_year = date.substring(0, 7) avec bascule automatique de vue resout un probleme que beaucoup d'applications de budget ratent : une saisie retroactive n'affecte jamais le mauvais mois.
